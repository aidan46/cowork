# v0.3.0 Plan

## Theme

Context packs, not chat.

v0.3.0 should make `cowork` useful in normal agent work: local model reads
targeted repo files, then returns compact JSON that cloud agents can consume
instead of raw file dumps.

## Goal

Ship one strong token-saving workflow:

```bash
cowork locate --paths src --recursive --thing "config precedence"
cowork brief --paths src/config.rs src/commands/ask.rs --goal "change config precedence safely"
```

`locate` finds likely files. `brief` turns selected files into concise,
evidence-backed context for another agent.

## Non-Goals

- no daemon
- no cache
- no index
- no provider abstraction
- no async runtime migration
- no broad repo analyzer
- no autonomous edit agent

## Product Bets

- `brief` is better than generic `summarize`, because `ask` already covers broad summaries.
- Savings should be shown as byte metrics, not vague token claims.
- CLI should own metadata, because model-reported timing and byte counts are not trustworthy.
- Output should be normalized before more commands get added.
- Docs should teach `locate` then `brief`, not whole-repo scans.

## Phase 1: Release Hygiene

Backfill release state before feature work.

Tasks:

- add v0.2.0 notes to `CHANGELOG.md`
- decide when `Cargo.toml` moves to `0.3.0`
- add release checklist note for package version, changelog, tag message, and GitHub release body

Acceptance:

- README makes no unsupported install claims
- `cargo metadata --no-deps` succeeds

## Phase 2: CLI-Owned Metrics

Move output metrics out of model JSON and into CLI wrapper logic.

Metrics:

- `input_bytes`
- `output_bytes`
- `duration_ms`
- `compression_ratio`

Apply to:

- `ask`
- `locate`
- `brief`

Acceptance:

- tests prove model cannot set authoritative duration or byte counts
- success JSON includes metrics
- parse errors stay strict
- serialization failures do not panic

## Phase 3: Output Normalization

Make JSON stable and compact.

Tasks:

- sort and dedupe `ask` rows like `locate`
- cap arrays with conservative fixed limits
- cap long strings with clear truncation marker
- add `risks` row when data is capped or truncated

Acceptance:

- tests cover duplicate rows
- tests cover stable sort
- tests cover caps and risk insertion
- no natural-language stdout warnings

## Phase 4: `cowork brief`

Add compact context pack command.

Command:

```bash
cowork brief \
  --paths <PATHS>... \
  --goal <GOAL> \
  [--model <MODEL>] \
  [--host <HOST>] \
  [--max-bytes <BYTES>] \
  [--recursive] \
  [--include <GLOB>] \
  [--exclude <GLOB>] \
  [--fail-on-missing]
```

Job:

- summarize only provided files
- explain each file role for goal
- list key symbols and responsibilities
- list evidence notes
- list missing-context risks
- suggest next reads

Not job:

- no edit plan
- no broad architecture essay
- no speculative files outside provided context
- no long raw excerpts

Schema shape:

```json
{
  "schema_version": "1.0",
  "command": "brief",
  "status": "ok",
  "goal": "change config precedence safely",
  "brief": {
    "summary": "Config precedence lives in src/config.rs.",
    "confidence": "high",
    "not_found": false
  },
  "files": [],
  "symbols": [],
  "evidence": [],
  "risks": [],
  "next_reads": [],
  "metadata": {
    "input_bytes": 5293,
    "output_bytes": 841,
    "duration_ms": 2134,
    "compression_ratio": "6.29"
  }
}
```

Acceptance:

- CLI parse tests for `--paths` and `--goal`
- prompt tests for brief schema
- parser tests for valid and invalid model JSON
- integration test with stub server
- README example for `locate` then `brief`

## Phase 5: Workflow Docs

Document real usage, not feature inventory.

Tasks:

- add README section: token-saving workflow
- show `locate` then `brief`
- explain byte metrics and limits
- warn that local model output is advisory
- keep install claims source-only unless release artifacts exist

Acceptance:

- commands copy cleanly
- docs avoid benchmark claims
- docs avoid whole-repo scan recommendation

## Phase 6: Agent Init Upgrade

Teach generated agent rules to use `brief`.

Tasks:

- update `cowork init codex --print`
- update `cowork init claude --print`
- update managed blocks from `--write`
- include `locate` first when unsure which files matter
- include `brief` when cloud context would otherwise need raw files

Acceptance:

- init print tests assert `brief` appears
- write tests remain idempotent
- user content outside markers stays untouched

## Phase 7: v0.3.0 Release

Release when feature and docs are complete.

Tasks:

- bump `Cargo.toml` to `0.3.0`
- update `CHANGELOG.md`
- add `.github/releases/v0.3.0.md`
- run full done checks
- open PR
- wait for checks
- after review, squash merge
- tag `v0.3.0`

Done checks:

- `taplo fmt --check Cargo.toml taplo.toml`
- `cargo fmt --all -- --check`
- `cargo nextest run`
- `cargo clippy --all-targets -- -D warnings`
- `cargo doc --no-deps --quiet`

## Suggested PR Sequence

1. `docs(release): backfill v0.2.0 changelog`
2. `refactor(output): move metrics into cli-owned metadata`
3. `refactor(output): normalize ask response rows`
4. `feat(brief): add compact context pack command`
5. `docs(readme): document token-saving workflow`
6. `feat(init): teach agents to use brief`
7. `chore(release): prepare v0.3.0`

## Open Decisions

- Should `compression_ratio` be string, decimal number, or omitted when output bytes are zero?
- Should `brief` include short evidence snippets, or only evidence notes?
- Should output caps be fixed constants first, or configurable later?
- Should `fail_on_missing` false behavior land in v0.3.0, or stay deferred?
- Should v0.2.0 changelog be backfilled even though package version was not bumped?
